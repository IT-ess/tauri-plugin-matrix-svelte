# CI/CD tasks — release pipeline

Status: phases run in order; tick a gate only once it passes, and start the next phase only after its gate is ticked.


## Context
There is no `.github/` directory, no CHANGELOG, and no updater. Releases (tags `0.2.0`…`0.4.0`, no `v` prefix) are built by hand, and iOS goes through `gen/apple/export-appstore.sh`. The goal is one GitHub Actions workflow that:
- bumps every version,
- writes a CHANGELOG entry,
- builds Windows / macOS arm64 / Linux (deb, rpm, AppImage) / Android / iOS,
- hosts the assets on CrabNebula Cloud (CN),
- creates a GitHub release that links to them,
- feeds tauri-plugin-updater.

The repo is public, so standard GitHub-hosted runners (including macOS arm64) cost nothing.

**Decisions made with the user:**
- **Trigger:** manual `workflow_dispatch` with a `patch|minor|major` input.
- **macOS:** signed and notarized.
- **iOS:** Ad Hoc IPA hosted on CN.
- **Windows:** unsigned for now.

**Tracking:** this file is the checklist. Each phase ends with a gate.

## Facts the design relies on (verified)
- **Version locations** (all currently `0.4.0`):
  - root `Cargo.toml` `[workspace.package].version` (the plugin and the example both inherit it)
  - root `package.json`
  - `example/matrix-svelte-client/package.json`
  - `src-tauri/tauri.conf.json`
  - `gen/apple/project.yml`: `CFBundleShortVersionString` and `CFBundleVersion`, in both the app and the NSE target
  - `gen/apple/matrix-svelte-client_iOS/Info.plist`
  - `gen/apple/NotificationService/Info.plist`
  - plus `Cargo.lock`
  - Android `versionName`/`versionCode` are derived by Tauri from tauri.conf, so nothing to edit there.
- **Not bumped:** the submodule `tauri-plugin-notifications` (`0.5.0-rc.14`) is a separate project.
- **Commits** follow Conventional Commits, so git-cliff can group them.
- **Submodule** is required (`submodules: recursive`). Git dependencies `matrix-ui-serializable` and `tauri-plugin-sharekit` are fetched over the network.
- **macOS:** `tauri.conf.json` contains `signingIdentity: "Developer ID Application: Alexis Loiseau (9A6YPCKFPC)"` and `embedded.provisionprofile: /Users/itess/...`, an absolute local path. CI overrides that path with `--config`.
- **Android:** `build.gradle.kts` reads `gen/android/keystore.properties` (`storeFile`, `keyAlias`, `password`). Only `.cargo/config.toml` tunes `aarch64-linux-android`. `google-services.json` is committed.
- **iOS:**
  - `tauri ios build` leaves the NSE appex unsigned, and its export uses automatic/cloud signing, which fails for this account.
  - `export-appstore.sh` fixes both problems using `ExportOptionsManual.plist`:
    - method `release-testing`
    - cert SHA1 `4A76…1329`
    - profiles `MatrixSvelteClientAdHocV3` and `MatrixSvelteClientNSEAdHocAppGroup`
  - The NSE SwiftPM package needs `tauri-plugin-notifications/.tauri/tauri-api`, which is generated by a cargo build for `aarch64-apple-ios`.
- **CN** (docs.crabnebula.dev/cloud/ci/tauri-v2-workflow):
  - draft → upload per platform → publish, all through `crabnebula-dev/cloud-release@v0`.
  - `release upload … --framework tauri` auto-detects bundles. Single files go in with `--file`.
  - Updater endpoint: `https://cdn.crabnebula.app/update/<org>/<app>/{{target}}-{{arch}}/{{current_version}}`.
  - Download URL: `https://cdn.crabnebula.app/download/<org>/<app>/latest/<file>` or `…/latest/platform/<public-platform>`.

## Phase 1 — Version bump + changelog (local first)
- **`scripts/bump-version.mjs <patch|minor|major>`** (plain Node, no dependencies):
  - computes the next version from root `package.json`
  - rewrites every file in the version list above with anchored regexes
  - prints the new version
- **`cliff.toml`** (git-cliff, Conventional Commits groups: feat/fix/perf/refactor/other, skip `chore(release)`).
  - Changelog entry: `git cliff --unreleased --tag <v> --prepend CHANGELOG.md`, covering commits since the previous tag.
  - Release notes: the same with `--strip all` written to a file.
- Seed `CHANGELOG.md` with a header only. History before 0.4.0 is not backfilled.

## Phase 3 — Workflow skeleton: prepare + draft + Linux (`.github/workflows/release.yml`)
- **Workflow settings:** `on: workflow_dispatch` (input `bump`), `concurrency: release` with `cancel-in-progress: false` (unlike the CN doc: a release must never be cancelled halfway), `env.CN_APPLICATION: refs/matrix-svelte-client`.
- **Job `prepare`** (ubuntu-24.04, `contents: write`):
  1. checkout with `fetch-depth: 0` and submodules
  2. set up Node 24 and pnpm
  3. bump script, then `cargo update -w`
  4. git-cliff (`orhun/git-cliff-action`) writes the CHANGELOG and `notes.md`
  5. commit `chore(release): X`, tag `X`, push main and the tag
  6. outputs: `version`; `notes.md` is passed on as an artifact
- **Job `draft`:** checkout at the tag, then `cloud-release` running `release draft $CN_APPLICATION --framework tauri --notes-file notes.md`.
- **Job `build_desktop`, Linux leg only for now** (ubuntu-22.04, chosen for the older glibc so the AppImage runs on more distros):
  - apt packages: `libwebkit2gtk-4.1-dev librsvg2-dev libssl-dev libayatana-appindicator3-dev libdbus-1-dev build-essential pkg-config`
  - Rust: `actions-rust-lang/setup-rust-toolchain` with cache, keyed per job
  - build from the example dir: `pnpm install --frozen-lockfile && pnpm tauri build`, with the `TAURI_SIGNING_*` env set
  - upload with `release upload … --framework tauri`
- Every build job checks out `ref: <tag>` with `submodules: recursive`.

- **As built (2026-10-04)** — what changed from the plan above:
  - **Bundle staging.** `cn --framework tauri` only finds bundles under `<dir>/target/**/release/bundle`, next to `tauri.conf.json`. Our `target/` is at the workspace root. Running `cn` from the example dir loops forever through `node_modules` → repo root. So each build job moves its bundles plus `tauri.conf.json` into `$RUNNER_TEMP/cn` and uploads from there. This was verified locally: `cn` finds the version and scans for assets.
  - **Rust setup.** `dtolnay/rust-toolchain` + `Swatinem/rust-cache`, not `actions-rust-lang/setup-rust-toolchain`. That action exports `RUSTFLAGS=-D warnings`, which overrides the `.cargo/config.toml` target flags and fails on any warning.
  - **Dry runs.** A dry run pushes the release commit to `ci-dryrun/<version>` (no tag). It drafts and uploads on the CN channel **`dryrun`**, so it never collides with real versions. Later jobs check out the exact commit SHA.
  - **Temporary push trigger.** `push: branches: [ci/release-pipeline]` is always a dry run. `workflow_dispatch` only works once the file is on main. **Remove it before merging.**
  - **Real releases** refuse to run outside `main`, and push `main` and the tag atomically.

  - **pnpm pinned** to 11.3.0 via `packageManager` in the root `package.json`. pnpm 11.28 rejects the git-hosted notifications API package unless `allowBuilds` lists its full tarball URL.
  - **Plugin JS package.** CI runs a root `pnpm build` before building the app: the example imports the plugin's JS package via `workspace:*`, and its `dist/` is gitignored.
  - **rpm upload.** cn 0.13.5 uploads `.rpm` only as a download, without its signature or update platform. CI stages the rpm separately and uploads it with `--update-platform linux-x86_64-rpm --public-platform rpm-x86_64`.
  - **Phase 7 links.** The deb's public platform is **`debian-x86_64`**, not `deb-x86_64` as the docs say.

## Phase 4 — Windows + macOS legs
- **Windows** (windows-latest): same build, unsigned. CN gets the NSIS and MSI installers plus their `.sig` files.
- **macOS** (macos-latest, arm64):
  1. decode `MACOS_PROVISION_PROFILE` to `$RUNNER_TEMP`
  2. write the `.p8` to `$RUNNER_TEMP` and set `APPLE_API_KEY_PATH`
  3. build: `pnpm tauri build --target aarch64-apple-darwin --config '{"bundle":{"macOS":{"files":{"embedded.provisionprofile":"'$RUNNER_TEMP'/profile.provisionprofile"}}}}'`
  4. env: `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY` (same string as in the conf), `APPLE_API_ISSUER`, `APPLE_API_KEY` (key ID), `APPLE_API_KEY_PATH`. Tauri imports the cert and notarizes by itself.

## Phase 5 — Android leg
- Runner ubuntu-latest, with:
  - JDK 25 (temurin, `actions/setup-java@v4`; Gradle 9.6 supports it)
  - `android-actions/setup-android@v3`
  - `nttld/setup-ndk` with `link-to-sdk` (pin the NDK version to the one used locally)
  - `rustup target add aarch64-linux-android`
- Write `gen/android/keystore.properties` exactly as the CN doc snippet does.
- Build: `pnpm tauri android build --apk --target aarch64`. A single ABI matches `.cargo/config.toml` and halves build time.
- Upload with `--framework tauri`. If CN doesn't pick up the APK, upload it explicitly with `--file <apk>`.

- [ ] **Gate 5:** the signed APK is on the CN draft, and it installs and logs in on a device. Also confirm a cold push still works, since R8 runs in release builds (see the memory note).

## Phase 7 — Publish + GitHub release
- **Job `publish`**, `needs: [prepare, build_desktop, build_android, build_ios]`:
  1. `cloud-release` runs `release publish $CN_APPLICATION --framework tauri`
  2. `gh release create X --notes-file body.md`, where `body.md` is `notes.md` plus a downloads table of CN links:
     - one row per platform (`dmg-aarch64`, `nsis-x86_64`, `deb-x86_64`, `rpm-x86_64`, `appimage-x86_64`, APK, IPA)
     - plus the link to the CN app page
  3. No binaries are attached to the GitHub release; it only references CN.
- **Recovery:** if a build leg fails, use "Re-run failed jobs". The tag and draft already exist, so re-running the whole workflow would bump again. Document this in `CI_CD_TASKS.md`.

## Free-tier notes
- Public repo, so standard runners (ubuntu, windows, macos arm64) are free and unlimited.
- Jobs run in parallel: 5 build jobs, well under the 20-concurrent-job limit.
- The rust cache shares a 10 GB repo cap. Use `Swatinem/rust-cache` (via setup-rust-toolchain) with `save-if` limited to the release workflow, so the matrix-sdk builds don't evict each other on every run.
